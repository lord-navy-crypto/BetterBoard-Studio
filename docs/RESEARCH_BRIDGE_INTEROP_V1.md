# Research Bridge interoperability v1

BetterBoard uses `betterboard.research-bridge/1.0` as the outbound experiment package contract.

## Capability negotiation

Consumers should inspect the capability manifest generated by `bridgeCapabilityManifest()` before exchanging derived results. The current contract advertises:

- outbound bridge schema: `betterboard.research-bridge/1.0`
- accepted Engineering Lab return schema: `engineering-lab.result/1.0`
- OpenPenguin context schema: `betterboard.openguin-context/1.0`
- append-only provenance
- immutable raw measurement evidence
- session-matched result import

Unknown fields should be ignored, but an unsupported schema must not be silently coerced.

## Engineering Lab result envelope

Engineering Lab returns derived results in this shape:

```json
{
  "schema": "engineering-lab.result/1.0",
  "source_bridge_schema": "betterboard.research-bridge/1.0",
  "session_id": "same-session-id-as-the-bridge",
  "created_at_utc": "2026-09-12T00:00:00Z",
  "producer": "Engineering Lab",
  "results": [
    {
      "id": "engineering-lab:analysis:...",
      "created_at_utc": "2026-09-12T00:00:00Z",
      "origin": "engineering-lab",
      "kind": "analysis",
      "text": "Derived analysis summary",
      "refs": ["result.csv"]
    }
  ],
  "artifacts": [],
  "warnings": []
}
```

Result events may use `analysis`, `warning`, or `decision`. They may not use `measurement`: Engineering Lab output is derived from BetterBoard evidence and must never impersonate the original sensor evidence.

## Import rules

BetterBoard rejects a return envelope when:

- the result schema is unsupported;
- `source_bridge_schema` does not match the supported BetterBoard bridge;
- `session_id` differs from the selected experiment session;
- a result event does not use `origin=engineering-lab`;
- an Engineering Lab result tries to claim `kind=measurement`;
- timestamps, identifiers, or bounded text fields are invalid;
- the envelope exceeds the bounded import limits.

Imports are deduplicated by event ID and appended to existing context. Existing raw evidence is not mutated.

## OpenPenguin boundary

OpenPenguin remains advisory. Its suggestions use `origin=openguin` and cannot enter the Engineering Lab result lane or raw measurement lane. This keeps measurement facts, human context, engineering analysis, and AI suggestions independently auditable.
